# Game Writing Rules (daisy V6, 7 rules)

These are the core rules separating **game prose** from **novel prose**. Daisy V6 distilled them after iterating on Claude-generated narrative; they're what make Script output feel like the reader is **playing**, not watching.

## Rule 1 — Player as agent

The protagonist DOES things. Active voice. The protagonist drives the action, not the narrator.

- Bad: `烛光摇曳，空气中弥漫着木头燃烧的味道，墙上挂着发黄的画像。`
- Good: `Su Wan推开木门，烛光在她掌心一跳。她伸手摘下墙上泛黄的画像背面那张夹着的借据。`

## Rule 2 — Show the world through interaction

Don't describe a room in a paragraph. Let the protagonist discover details by touching, examining, talking.

- Bad: `抽屉里静静躺着一把钥匙。`
- Good: `Su Wan拉开抽屉。一把生锈的钥匙，还有一张被咖啡渍洇过的字条。`

## Rule 3 — Keep it punchy

Short sentences for action. Max 2-3 sentences of description before something HAPPENS (dialogue, discovery, event, decision). No long atmospheric paragraphs.

- Bad: 4 sentences of weather and mood before any action.
- Good: 1-2 sentences of setting → action/dialogue → consequence.

## Rule 4 — Concrete game information

Include things the player cares about: objects they can use, NPCs they can talk to, threats they need to handle, clues they find. Every detail should be actionable or foreshadow something actionable.

- Bad: `她觉得这里很可疑。` (abstract; player has nothing to grab)
- Good: `桌上堆着三份合同，日期都划了X。` (concrete; player sees the clue)

## Rule 5 — Dialogue is gameplay

NPC dialogue reveals information, presents dilemmas, or creates tension. NPCs have distinct voices and agendas. Keep exchanges short and sharp.

- Bad: `「欢迎来到本店，」他微笑着说，「我们有很多好东西。」` (no info, no stakes)
- Good: `「你的事务所上周赢了三件民事。」他把玫瑰递过来，「谁在背后付钱？」` (info + stakes in one line)

## Rule 6 — Tension through stakes, not prose

Create tension through WHAT happens (time pressure, scarce resources, difficult choices), not HOW it's described.

- Bad: `空气仿佛凝固，每一秒都像一个世纪。` (purple prose, zero stakes)
- Good: `氧气表：剩余三小时。她还没找到那把钥匙。` (concrete stake, bare prose)

## Rule 7 — Setup nodes are active too

Even world-building scenes should have the protagonist DOING something (exploring, talking, investigating), not passively observing. The "establishing beat" still has the PC exploring / talking / working.

- Bad: `这是一座繁华的东方都市，霓虹闪烁，人群熙攘。`
- Good: `Su Wan走出写字楼，被地铁口的风掀了一下裙摆。她下意识拎起裙角，雨点落在她腕表的玻璃面上。`

## Rule 8 — Dialogue is rendered, never mentioned

Rule 5 says *when there is dialogue, each line must carry gameplay weight*. Rule 8 closes the sibling loophole: **you cannot remove the dialogue by narrating-over it**.

If the beat contains a character-to-character exchange, that exchange MUST appear as explicit spoken lines (「」-quoted) on the page. Summaries of exchanges, narrations of exchanges, and elisions of exchanges all fail this rule because they reduce the scene from present-tense witness to past-tense narration — the reader is told a conversation happened instead of witnessing it.

Test: read the beat aloud to yourself. Can you *hear* the characters speak, in their own voices, saying distinguishable sentences? If no — if you heard only the narrator summarizing the fact of a conversation — rewrite so every key line is on the page.

This applies most strictly to value-shift moments: whenever the beat's `valueBefore → valueAfter` hinges on what a character says, the exact lines are load-bearing and cannot be summarized.

## When these rules don't apply

- **Dreams / memory / voiceover** — a brief interior scene can be 3-4 sentences of description without action. But don't do this more than once per story.
- **Climax beats** — can slow down for one decisive image/action. But the decision itself is still active.
- **Epilogue / endings** — can be more reflective. But still avoid purple prose.

## Mode-specific adjustments

- **Poetic mode + detailed**: rules still apply, but metaphorical language allowed in descriptions. Keep the ACTION rule strict.
- **Literal mode + detailed**: rules strict. Write "like a game script, not poetry" (daisy V6's exact phrasing).
- **Extreme mode**: rules MORE strict — each beat is 40-80 words so there's no room for filler.
